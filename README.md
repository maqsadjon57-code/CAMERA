Полнофункциональный веб-сервис **Real-Time AI HUD**: рендеринг HUD-оверлеев выполняется
на стороне Python (OpenCV), а в браузер отдаётся **MJPEG-поток** готовых кадров.
Веб-интерфейс (HTML/CSS/JS, встроен в `app.py`) работает на компьютере и на смартфоне.

| Сценарий | Что делает |
|---|---|
| 🚗 **Автомобиль** (vehicle) | Телеметрия OBD-II (RPM 800–5000, температура 80–115 °C, вибрация 0.0–1.0), детекция узлов (`Engine_Block`, `Belt_Pulley`, `Dashboard`, `Check_Engine_Light`), диагностика: `CHP-0402 Bolt Wear Detected` (Belt_Pulley conf > 80 % + вибрация > 0.9) и `CHP-0031 Overheating Risk` (t > 105 °C). Журнал ошибок — в боковой панели. |
| 🎓 **Студенты** (student) | Детекция людей (YOLOv8, класс 0), анализ поз (MediaPipe: наклон головы, поднятая рука). Классификация: `Actively Participating` / `Distracted` / `Confused` / `Focused`. Стабильные ID (`STD-0001`…), `PRED. SCORE` 0–100 и рейтинг активности в боковой панели. |

## 🚀 Быстрый старт

```bash
# 1. Установить зависимости (Python 3.10+)
pip install -r requirements.txt

# 2. Запустить
python app.py                              # камера устройства включается кнопкой в браузере
python app.py --input 0                    # веб-камера, подключённая к серверу (локальный запуск)
python app.py --input http://192.168.1.100:8080/video   # IP-камера смартфона
python app.py --input synth                # встроенная демо-сцена

# 3. Открыть в браузере на компьютере
#    http://127.0.0.1:5000
```

## 🎥 Реальный режим: камера устройства (запрос разрешения)

При первом открытии страницы поверх видео появляется экран **«Разрешите доступ к камере»**:

1. Нажмите **«Разрешить доступ к камере»** → браузер покажет стандартный запрос разрешения (getUserMedia).
2. После разрешения кадры с камеры вашего устройства (~12 к/с, JPEG 640px) отправляются
   на сервер (`POST /api/push_frame`), где выполняются **настоящий инференс и отрисовка HUD** —
   обратно в браузер приходит MJPEG-поток с рамками, статусами и телеметрией.
3. Источник также включается кнопкой **«🎥 Камера устройства»** в панели «Источник видео»
   или значением `browser` в поле источника. Остановить — кнопка **«⏹ Остановить камеру»**.

Требования к доступу камеры: страница открыта по **HTTPS** или **localhost**. Если превью
открыто во встроенном окне (iframe) и браузер блокирует камеру — откройте адрес страницы
в отдельной вкладке браузера.

Что работает по реальному видео:

| Компонент | Реальная камера |
|---|---|
| YOLOv8 (веса скачаны, нужен интернет при первом запуске) | детекция людей/объектов — настоящие рамки |
| Без весов YOLO (офлайн) | режим «Студенты»: встроенный **HOG-детектор людей OpenCV** (реальный); режим «Автомобиль»: телеметрия и диагностика без рамок |
| MediaPipe (модель скачана) | анализ поз: поднятая рука, наклон головы |
| Без MediaPipe | эвристические статусы (помечается в чипе «ПОЗЫ») |

Демо-сцена включается только если камеры нет / доступ запрещён — и всегда отключается,
как только реальная камера начинает передавать кадры.

## 📱 Запуск на телефоне — три способа

| Способ | Как |
|---|---|
| **1. Установить как приложение (PWA)** | Откройте страницу → меню браузера → «Установить приложение» (Android) или «Поделиться» → «На экран Домой» (iOS). Иконка появится на главном экране, приложение откроется на весь экран без адресной строки. |
| **2. Телефон — клиент, сервер на ПК** | Телефон и компьютер в одной Wi-Fi. Наведите камеру телефона на **QR-код** в боковой панели (адрес сервера) и откройте страницу. Для работы **камеры телефона** нужен HTTPS: запустите `python app.py --https` и откройте `https://<IP-ПК>:5000` (подтвердите исключение для самоподписанного сертификата). |
| **3. Сервер прямо на телефоне (Termux)** | Установите [Termux](https://f-droid.org/packages/com.termux/) (F-Droid), скопируйте папку проекта на телефон и выполните `bash run_phone.sh`, затем откройте в браузере телефона `http://127.0.0.1:5000`. Это localhost — **камера работает сразу, без HTTPS**. |

Детали способа 3 (сервер на телефоне):

- Достаточно лёгких зависимостей: `requirements-phone.txt` (flask + numpy + qrcode + opencv 4.x из репозитория Termux) — **YOLOv8/MediaPipe не нужны**: работают встроенный HOG-детектор людей и эвристические позы.
- Брандмауэр Windows (если телефон не открывает страницу по Wi-Fi, cmd от админа):
  `netsh advfirewall firewall add rule name="AI HUD" dir=in action=allow protocol=TCP localport=5000`

> ℹ️ **Про ошибку «Missing Traffic Access Token»:** это защита облачного превью Arena/e2b —
> адрес `https://5000-…e2b.app` открыт только из окна превью (платформа подписывает запросы
> токеном). Открыть его с телефона или из новой вкладки нельзя. Приложение определяет это
> автоматически (`sandboxed` в `/api/state`): в превью QR-код заменяется инструкцией, а при
> запуске на своём ПК/телефоне всё работает как описано выше.

## 📹 Телефон как IP-камера

1. Установите **«IP Webcam»** (Google Play, автор Pavel Khlebovich); аналог для iOS — iVCam / DroidCam.
2. Телефон и компьютер — в одной Wi-Fi сети.
3. В приложении нажмите «Запустить сервер» — на экране появится адрес, например `http://192.168.1.100:8080`.
4. Вставьте `http://192.168.1.100:8080/video` в поле **«Источник видео»** на странице и нажмите
   **«Подключить»** — источник сменится **без перезапуска** программы.

## 🌐 Веб-интерфейс

- Основная область — живой MJPEG-поток (`<img src="/video_feed">`), кнопки «Переподключить поток»,
  «Снимок кадра», «Во весь экран».
- Кнопки **«Автомобиль» / «Студенты»** — мгновенное переключение логики инференса (POST `/api/mode`).
- Боковая панель: источник видео, телеметрия OBD-II с индикаторами, **журнал событий**,
  **рейтинг студентов**, справка. На экранах уже 960 px панель переезжает под видео (mobile-friendly).

## 🔌 REST API

| Метод | Endpoint | Описание |
|---|---|---|
| GET | `/` | Веб-интерфейс |
| GET | `/video_feed` | MJPEG-поток HUD |
| GET | `/api/state` | Режим, источник, камера, FPS, телеметрия, статус DTC |
| GET | `/api/events?limit=40` | Журнал событий |
| GET | `/api/students` | Рейтинг студентов |
| GET | `/api/snapshot` | JPEG-снимок текущего кадра |
| POST | `/api/mode` | `{"mode": "vehicle" \| "student"}` |
| POST | `/api/source` | `{"source": "browser" \| "0" \| "synth" \| "http://..."}` |
| POST | `/api/push_frame` | тело = JPEG-кадр с камеры устройства (шлёт браузер) |

## 🏗️ Архитектура (все потоки не блокируют друг друга)

```
VehicleTelemetry ─┐                       ┌─► EventBus ──► /api/events
(поток, 0.12 c)   ├─► HUDPipeline ─► JPEG ─┤
ThreadedVideo     │   (YOLOv8 + MediaPipe  └─► /video_feed (MJPEG, все клиенты)
Capture (поток) ──┘   + рендер HUD)            читают один и тот же буфер
Queue(maxsize=1): всегда самый свежий кадр, старые отбрасываются (anti-lag)
```

Классы: `ThreadedVideoCapture`, `YOLOInference` (+`SyntheticDetector` fallback),
`TelemetrySimulator`/`VehicleTelemetry`, `OverlayRenderer`, `StudentPoseAnalyzer`,
`SimpleTracker`, `VehicleDiagnostic`, `HUDPipeline`, `EventBus`.

**Graceful degradation:** если веб-камера недоступна — включается встроенная синтетическая
демо-сцена (моторный отсек / аудитория); если модель YOLOv8 не скачалась (нет интернета) —
работает синтетический детектор; если MediaPipe недоступен — эвристический анализ поз.
Приложение остаётся полностью работоспособным в любом окружении.

> ⚠️ Классы `Engine_Block / Belt_Pulley / Dashboard / Check_Engine_Light` отсутствуют в
> предобученной COCO-модели: в демо их метки отображаются на словарь из задания, для боевого
> применения дообучите YOLOv8 на собственном датасете (data.yaml с этими 4 классами).

## ⚙️ Параметры запуска

```
--input    источник: browser | 0 | http://.../video | synth | video.mp4   (по умолчанию 0)
--host     адрес сервера, по умолчанию 0.0.0.0 (доступ с телефона)
--port     порт, по умолчанию 5000
--https    HTTPS с самоподписанным сертификатом (камера телефона по Wi-Fi)
--model    yolov8n.pt / yolov8s.pt ...
--conf     порог уверенности детекции (0.35)
--width    рабочая ширина кадра (960)
--max-fps  ограничение FPS конвейера (24)
```
